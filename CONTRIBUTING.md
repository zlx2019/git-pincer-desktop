# Contributing Guide

Thank you for contributing. Please read the following guidelines before submitting changes.

## Development Environment

### Rust Toolchain

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

The project pins its Rust version in `rust-toolchain.toml` (Rust sources live in `src-tauri/`). After entering the project directory, `rustup` will automatically install the required toolchain and components when needed.

### Frontend Toolchain

```bash
# Node.js >= 22 with pnpm
pnpm install
```

### Development Tools

```bash
cargo install --locked cargo-deny     # Dependency security and license auditing
cargo install --locked typos-cli      # Spell checking
cargo install --locked git-cliff      # Changelog generation
cargo install --locked cargo-nextest  # Enhanced test runner
pip install pre-commit                # Git pre-commit checks
```

### Run The App

```bash
pnpm tauri dev
```

Test data can be generated with the playground example of the sibling [git-pincer](https://github.com/zlx2019/git-pincer) repository.

### Enable Pre-Commit

```bash
pre-commit install
```

After installation, each `git commit` will run fmt, deny, typos, svelte-check, check, clippy, and test checks. The commit will only succeed when all checks pass.

## Local Checks

Before submitting changes, make sure the following commands pass:

```bash
pnpm check && pnpm build              # frontend type check + build (build/ is required by cargo checks below)
cd src-tauri
cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo nextest run --all-features --no-tests pass
cargo deny check
typos
```

## Commit Convention

Commit messages follow [Conventional Commits](https://www.conventionalcommits.org/):

| Type | Description |
|------|-------------|
| `feat:` | New feature |
| `fix:` | Bug fix |
| `docs:` | Documentation change |
| `refactor:` | Refactor that is neither a feature nor a bug fix |
| `perf:` | Performance improvement |
| `test:` | Test-related change |
| `chore:` | Build, toolchain, or miscellaneous maintenance |

The changelog is generated by git-cliff from commit history, so keep commit messages consistent.

## Branches And Pull Requests

- Create feature branches from `main`.
- Keep each pull request focused on a single topic.
- Pull requests must pass CI checks, including lint, test, deny, typos, and the frontend check.

## Release Process

The version lives in two files — `package.json` (the authority; `src-tauri/Tauri.toml`
inherits it via `version = "../package.json"`, which drives artifact versions and the
in-app About panel) and `src-tauri/Cargo.toml` (the crate version). One command keeps
them in sync, regenerates the changelog, commits (running the full pre-commit gates)
and tags:

```bash
scripts/bump.sh 0.x.y
# then publish — this is what triggers the four-platform release matrix
# (dmg / nsis+msi / AppImage+deb+rpm) and drafts the GitHub release:
git push && git push --tags
```

Release notes are generated by git-cliff from commit history; commits with
non-English (e.g. Chinese) messages are skipped by `cliff.toml` and will not
appear in the notes.
